## What Happened

Completed retroactive hardening pass across phases 01a through 06 (7 phases total, 42 scenarios). Fixed 10 critical issues, 14 high, 11 medium. Three critical bugs surfaced during code review that had silently shipped.

## The Brutal Truth

The HIGH-2 bug stings: `enqueueReceiptEmail` was sending **phone numbers as email addresses**. Every approved receipt—hundreds of them—had `parentPhone` jammed into the SMTP `to` field. The transport layer never validated email format; it just accepted whatever was passed. This means parent notifications were silently discarding for months with no logging or bounce indication.

The timing oracle in `loginStudent` is worse because it's **measurable**. The code had two branches: `studentAccounts.length === 0` returns instantly (~70ms), but wrong-password verification takes ~140ms (bcrypt hashing). An attacker timing the response can enumerate valid student accounts. This is textbook OWASP A07:2021 (Identification and Authentication Failures). It shipped.

## Root Cause Analysis

The email bug: no input validation at the function boundary. The function name was misleading (`parentPhone` parameter for an email transport). No contract checking.

The timing oracle: branching on account existence before constant-time verification. Pattern review was insufficient—this needs automated scan.

## Lessons Learned

- **Encrypt contract at function boundaries**: Email functions must assert `isValidEmail(input)` at entry, not hope caller got it right
- **All auth branches must have identical timing**: Use constant-time verification even for "early exit" paths
- **Transport layer needs format validation**: SMTP should validate email before attempting send, log failures explicitly
- **Scenario testing finds what code review misses**: 42 scenarios across 7 phases caught patterns code inspection alone didn't surface
