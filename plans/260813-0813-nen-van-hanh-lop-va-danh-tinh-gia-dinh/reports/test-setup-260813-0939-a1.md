### Bẫy CREATE ROLE — còn đúng

**Còn đúng.** Xác minh trên source hiện tại.

Migration `packages/db/prisma/migrations/20260706054322_p1_remediation_wave1_schema_rls/migration.sql:147-155`:

```sql
-- No password is set here (this file is committed to git) — set one
-- out-of-band per environment: `ALTER ROLE cmc_app WITH PASSWORD '...';`.
DO $$
BEGIN
  IF NOT EXISTS (SELECT FROM pg_catalog.pg_roles WHERE rolname = 'cmc_app') THEN
    CREATE ROLE "cmc_app" LOGIN NOSUPERUSER NOBYPASSRLS NOCREATEDB NOCREATEROLE NOINHERIT;
  END IF;
END
$$;
```

Hệ quả:

1. `prisma migrate deploy` **tạo** `cmc_app` nếu chưa có, **không** đặt mật khẩu.
2. `CREATE ROLE cmc_app ...` sau migrate **lỗi** (role đã tồn tại). Mật khẩu vẫn trống.
3. `APP_DATABASE_URL` dùng password → auth fail → hàng trăm test đỏ giả (không phải bug A1). Nhật ký thật: `plans/reports/execution-260723-1042-don-tien-uat-phase-1-2-4.md` (784/986 đỏ khi thiếu URL/role).

Cách đúng — mọi script chuẩn đều dùng `ALTER ROLE`, không `CREATE ROLE` sau migrate:

```bash
# CI — .github/workflows/ci.yml:71-74
PGPASSWORD=postgres psql -h localhost -U postgres -d cmc_ci \
  -c "ALTER ROLE cmc_app WITH PASSWORD '${CMC_APP_PASSWORD}';"

# Synth — scripts/synthetic-seed-env.sh:81-83
docker exec "$CONTAINER" psql -U postgres -d "$DB_NAME" \
  -c "ALTER ROLE cmc_app WITH PASSWORD '${PG_PASSWORD}'"
```

Ngoại lệ: host DR trống, role chưa tồn tại — `docs/runbook-deploy.md:82-83` cho phép `CREATE ROLE` **trước** `pg_restore`. Đó không phải đường test.

Sắc thái: `IF NOT EXISTS` trong migration nghĩa là **chạy lại migrate không gãy**. Bẫy không nằm ở migrate lần hai; nằm ở người/script gõ `CREATE ROLE` để “đặt password”.
