## P3: Dependabot + SAFE CVE overrides

**Deviation from the literal instruction, evidence-based:** the task said add a single
`"brace-expansion": "^2.1.2"` override. Live `pnpm audit` showed brace-expansion is
vulnerable in **two independent major-version lines** under the same advisory
(GHSA-mh99-v99m-4gvg): `>=2.0.0 <2.1.3` (via `ts-morph > @ts-morph/common > minimatch@9`)
and `>=4.0.0 <5.0.8` (via `eslint`/`typescript-eslint` `> minimatch@10`, resolved at 5.0.7).
A flat `^2.1.2` override would have forced pnpm to downgrade the eslint-side dependency
from major 5 to major 2 — that is a breaking major change disguised as a patch, not a
safe fix, and risks silently changing minimatch's brace-expansion behavior for the
linter used by CI/pre-commit. Used pnpm's path-scoped override syntax instead so each
major line gets its own real patch bump, no major-version movement for either consumer:

```json
"overrides": {
  "fast-uri": "^3.1.4",
  "minimatch@9>brace-expansion": "^2.1.3",
  "brace-expansion": "^5.0.8"
}
```
(the bare `"brace-expansion"` key now only needs to reach the 5.x line already in use by
`minimatch@10`; the `minimatch@9>...` scoped key pins the ts-morph-side 2.x line.)

- `react-router` (7→8 major), `vitest` (2→3 major), `vite` (5→6 major, coupled to vitest)
  intentionally **left untouched** per instructions — deferred to Dependabot / a reviewed
  breaking-change PR. `postcss` (HIGH, transitively pulled in by `vite`) is in the same
  deferred bucket — it resolves once `vite` is bumped, not independently overridable
  without risking a mismatched postcss/vite pairing.

## P2: husky + lint-staged pre-commit

`pnpm add -Dw husky lint-staged` → `husky@9.1.7`, `lint-staged@17.3.0`.

Added to root `package.json`:
- `"prepare": "husky"` script.
- `"lint-staged": { "apps/{admin,lms}/**/*.{ts,tsx}": "eslint --no-warn-ignored --max-warnings=0" }`
  — scoped glob per red-team C1 (repo's `eslint.config.js` only configures
  `apps/admin/**` and `apps/lms/**`; a repo-wide glob would make ESLint 10 flat config
  emit "File ignored" warnings for out-of-scope staged files, and
  `--max-warnings=0` would then fail on those warnings, blocking nearly every commit).

Ran `pnpm run prepare` → husky set `core.hooksPath` to `.husky/_`, generated hook
delegators there (self-`.gitignore`d, nothing to commit from `.husky/_/`).

Created `.husky/pre-commit` (chmod +x):
```sh
pnpm exec lint-staged || exit 1

if command -v gitleaks >/dev/null 2>&1; then
  gitleaks protect --staged --redact --config .gitleaks.toml || exit 1
else
  echo "gitleaks not on PATH — skipping local staged secret scan (GitHub push protection is the backstop)."
fi
```
gitleaks is best-effort (does not hard-fail when absent) per instructions — GitHub-native
push protection (Phase 5, already enabled server-side) is the backstop.
